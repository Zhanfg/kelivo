# Visual Taste Basics

用于设计、评审或改写界面时保持克制、清晰和真实的产品感。它参考 `Leonxlnx/taste-skill` 的方向，但保留 Kelivo 自己的 Material 3 / Dynamic Color / 原生交互约束。

## 核心规则

- 先解决信息架构、任务路径和视觉层级，再加装饰。
- 不要把每个内容块都做成圆角卡片。只有存在真正的分组、层级或可交互边界时才使用 surface/card。
- 避免“AI Dashboard”套路：巨型标题、空洞副标题、四张统计卡、无来源假指标、满屏 badges/pills、装饰性图表。
- 避免无目的渐变、霓虹光、玻璃拟态、发光边框和过度阴影。若产品已有 Material 3 / Dynamic Color，应优先使用系统色彩角色和 surface 层级。
- 圆角、间距、图标大小必须来自一致的设计尺度；不要为了“高级感”把所有元素都做得又大又圆。
- 用字体大小、字重、留白和对齐建立层级，不靠大量边框与背景色切块。
- 按钮层级必须体现真实优先级：一个区域通常只有一个主要动作；次要动作使用 tonal/text/icon 等较弱表现。
- 不制造假数据、假用户评价、假状态或假业务指标来填满页面。
- 图标应表达动作或对象，不拿 emoji 当默认 UI 图标；有现有图标体系时继续沿用。
- 文案直接说明动作和结果，避免“Unlock the power of… / Elevate your experience…”一类营销占位句。
- 响应式布局不是简单缩放：手机优先单列和触控目标，桌面允许更高信息密度，但保持同一信息关系。
- 动画只用于解释状态变化、空间关系或反馈。避免持续漂浮、无意义 shimmer、过度弹跳和全局转场。
- 可访问性优先于视觉噱头：对比度、字号、触控面积、Reduced Motion、键盘/读屏语义不能因“审美”被牺牲。

## Kelivo 特化

- 尊重 Material 3 与 Dynamic Color，不硬编码一套品牌色覆盖用户主题。
- 原生已有组件能表达语义时优先复用；新交互结构可以创新，但不要做一套与 Kelivo 视觉系统割裂的“网页套壳”。
- Story Runtime 的沉浸效果必须与 Agent Runtime 的真实安全/审批 UI 明确区分，不能让故事特效伪装成 MCP 授权、删除确认、密码或系统错误。

## 判断标准

完成设计后检查：用户能否第一眼知道“这里是什么、当前状态是什么、下一步能做什么”；如果必须依赖大量装饰卡片、标签和说明文字才能理解，先重做结构，而不是继续美化。
